# External calendar synchronization

The twelve `/api/v1/calendar-sync` operations implement Google/Microsoft connections, manual two-way synchronization, stable mappings, explicit conflicts, and ICS import/export. Each connection belongs to one active internal user and one writable Calendar. Workspace owners may inspect other users' connection metadata; only the connection owner may synchronize, disconnect or resolve its conflicts. Platform permissions `calendar_sync.connect`, `.read`, `.run` and `.resolve` remain mandatory, together with owning Calendar/Event authority.

Configure `CALENDAR_SYNC_BROKER_URL` and `CALENDAR_SYNC_BROKER_TOKEN` for the trusted Integration service. HTTPS is required except for loopback development. The broker owns OAuth credentials, authorization-code exchange, refresh/revocation, Google Calendar and Microsoft Graph API adaptation. The application persists only an opaque credential reference in `integration_calendar_credentials`. Credentials, authorization codes and broker tokens are omitted from Calendar responses, Audit and outbox payloads. An unconfigured broker returns `CALENDAR_SYNC_PROVIDER_ERROR`.

The broker accepts authenticated JSON `POST /connect`, `/pull` and `/push`, using `Authorization: Bearer <configured token>` and `Idempotency-Key`. Every response includes the matching `connectionId`. All requests carry `workspaceId`, `connectionId` and `provider` (`GOOGLE` or `MICROSOFT`).

* Connect receives `userId`, `authorizationCode`, HTTPS `redirectUri` and optional `externalCalendarId`; it returns `credentialRef`, `externalCalendarId` and optional `accountEmail`.
* Pull receives `credentialRef`, `externalCalendarId` and nullable `cursor`; it returns `events` (at most 5,000) and `nextCursor`. An event has `externalEventId`, `etag`, `title`, `description`, `location`, `status`, `isAllDay`, `startAt`, `endAt`, `startDate`, `endDate`, `sourceTimezone` and optional `origin: { connectionId, localVersion }`. Timed values are offset-qualified ISO instants; all-day values use exclusive end dates.
* Push receives the same identity plus nullable `externalEventId`, an Event snapshot (including `localEventId`, `localVersion`, optional `rrule` and `origin`), and `idempotencyKey`; it returns `externalEventId` and `etag`. The broker must persist idempotency results per connection/local Event/version, preventing duplicate vendor Events after process crashes or partial batches.

Sync commits a five-minute lease before provider I/O, then rechecks live authorization and applies changes in a separate transaction. Pull occurs before push; an externally changed mapping is withheld from outbound writes. Concurrent local/provider edits create an OPEN conflict. LOCAL and MERGED resolutions enqueue the local version for the next run; EXTERNAL applies the provider snapshot; IGNORED accepts the observed pair. Resolution requires the current conflict version and unchanged local Event version. Expired workers cannot finalize a newer claim. Provider failure releases the claim and records visible failure/outbox evidence; revoked authorization sets AUTH_REQUIRED. Disconnect irreversibly revokes the local credential reference while preserving Event/mapping history, and emits `CALENDAR_SYNC_DISCONNECTED`. The Integration outbox consumer must revoke the corresponding vendor credential.

ICS import is bounded to 1 MiB and 2,000 Events, never fetches URLs, and maps stable UIDs within a named source. Timed Events support UTC, IANA TZID and floating values interpreted in the target Calendar timezone; all-day dates retain exclusive ends. Supported RRULEs use the owning recurrence service. Unsupported recurrence overrides, EXDATE/RDATE and unusable UIDs produce explicit warnings. Export returns `text/calendar` with private/no-store headers and only Events the caller may read. There is no public export capability.

Automated tests exercise a deterministic authenticated HTTP broker, provider retry/revocation, mapping deduplication, echoes, conflicts, leases, SQL invariants, tenant/auth boundaries, ICS and audit/outbox. Deployment smoke testing must exercise real Google/Microsoft consent, token refresh/revocation, provider delta pagination and idempotent writes through the configured broker. Configure the disconnect outbox consumer as part of that deployment.

Each run pushes at most ten local changes to stay within the lease at the broker timeout. The response includes pendingPushCount; repeat the command while it is nonzero. Pulled provider pages advance only after the whole application transaction succeeds.
