# Generic File attachments

GET/POST /api/v1/attachments, GET/DELETE /api/v1/attachments/:id and GET /api/v1/entities/:entityType/:entityId/attachments bind one existing logical File without copying bytes. POST accepts fileId, entityType, entityId and optional role (ATTACHMENT default; RESULT, COVER, DOCUMENT, MEDIA or OTHER). Identity is immutable. Repeated identical bindings return the existing row without duplicate events.

Reads require file.read, current File ACL, clean processed active content and readable owning context. Lists omit inaccessible bindings before pagination and totals. Attach requires file.attach plus current File access and the target module's read and mutation policies. Detach requires file.detach, File access and mutable target authority; it permits trash/quarantine cleanup without opening bytes. Workspace owners may remove persisted orphan references after the owning record is deleted. Cross-Workspace and missing IDs reveal no foreign metadata.

Registered targets: TASK, TASK_TEMPLATE, PROJECT, CALENDAR_EVENT, CHAT, LEAD, DEAL, CONTACT, COMPANY, ACTIVITY and PRODUCT. Owning modules register their policies; unsupported target types fail closed. Future Messages, Feed and Documents integrations must register real owning authority when those modules exist. CRM/Catalog adapters come from the existing entity registry. Archived Projects and Events/Chats enforce owning-module read-only policies.

Binding creation/detach advances the File share revision, retiring old delivery grants. Downloads and copies require all private owning contexts, including generic bindings and existing Task/Calendar, Activity, Timeline, Product media and FILE custom-field references. Contextual attachment reads require their selected target and current File authority. Public links never expose privately bound content. The default shared FilePort now validates real Files; tests may override it with an explicit adapter.

Detachment retains the File, Versions and bytes. Business-object deletion preserves shared File data. Permanent File/folder purge refuses generic bindings with FILE_HAS_ATTACHMENTS; detach first, then existing retention and legal-hold rules still apply. Immutable deduplicated attachment rows have same-Workspace File/target guards and provenance. Workspace revisions fence concurrent owning-policy changes and roll back stale mutations and byte delivery.

FILE_ATTACHED/FILE_DETACHED events commit through the transactional outbox. Central FILE.ATTACHED/FILE.DETACHED audit evidence is recorded when Workspace settings.auditFileAttachments is true. No new background job or external provider is introduced.
