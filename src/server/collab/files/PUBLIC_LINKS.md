# Public File and folder capabilities

File/folder link creation requires `file.public_link_manage` and effective FULL authority on an active resource. The creation response returns a 256-bit URL-safe secret once; persistence keeps its SHA-256 hash. Management responses and audit/outbox payloads omit token and password hashes. Passwords use Argon2 and public requests supply them through `X-Share-Password`, never a URL parameter.

Links expire after 30 days by default, bounded by `workspace.settings.publicLinkMaxExpiryDays` (default 365). Explicit expiry must be a future instant within that maximum. `publicLinksEnabled: false` disables creation and public access. PATCH requires a resource version; DELETE permanently revokes the capability and cannot be undone. A new link is required after revocation or trash.

Public folder reads validate the secret, live policy, expiry, revocation, password, folder share version, issuer eligibility, current issuer authority and the active storage/ancestor chain. They never create Workspace membership. `includeChildren` defaults false. When enabled, `folderId` can select a currently reachable, issuer-readable descendant. Moving a folder outside the shared tree removes that access. Restricted branches are omitted. Returned metadata contains only folder IDs/names/parent relationships and permission mode; no Workspace audiences or storage secrets are disclosed.

Trash increments share versions across its subtree. Restoring a folder does not restore a previous link. Purge removes associated capability records in the same transaction before deleting folders. Database guards protect token/resource identity and prevent reactivation or counter rollback. Successful public reads advance a durable access counter and record audit/outbox evidence with a hashed client identifier. This counter also participates in the Workspace revision fence, so stale cross-worker reads cannot commit after policy, issuer, ACL, graph or link changes.

The public HTTP route applies the existing request rate limiter and returns `Cache-Control: private, no-store` and `Referrer-Policy: no-referrer`. The limiter is process-local, consistent with the repository's other public routes; deployments needing a shared fleet limit must supply that at the ingress layer.

File links use `/api/v1/public/files/:token` and cannot include children. Public metadata contains only File identity/name, MIME type, byte size and current Version identity/resource version. It requires ACTIVE content with a CLEAN, processed current Version, plus the live issuer's FULL File authority and all policy/password/lifecycle checks. File tokens are rejected by folder routes and folder tokens by File routes. Common list/read/update/revoke operations support both types. Direct File trash and ancestor folder trash invalidate old capabilities permanently across restore; File/folder purge removes File links transactionally.

Anonymous access cannot satisfy private business-record authority. File capabilities reject content bound to existing Task results, Task templates or Calendar Events, and access is denied if a binding is subsequently added. These bindings participate in the Workspace revision fence, so a concurrent independent binding change rolls back stale public-access counters and audit/outbox evidence. Generic attachments must use the same gate once their binding service is implemented. Public sharing of business-bound content requires an explicit owning-module public policy.

File and folder content copies require readable owning records before cloning any Version. This prevents a File-only reader from stripping an unreadable private binding by copying the content into an unbound logical File. Folder copy checks the complete source graph before creating destination metadata.

`GET /api/v1/public/files/:token/download` validates the link/password and returns a two-minute signed delivery path. DOWNLOAD permission is required; VIEW permits metadata reads. The durable grant captures link identity/version and exact File Version/share revision, with expiry capped by link expiry. Every byte redemption rechecks issuer eligibility, File download authority, live sharing policy, revocation, expiry, private bindings and scan/processing proof. Password and other link edits invalidate outstanding grants. No anonymous Workspace actor is created.

Folder reads also return clean, processed, issuer-readable File metadata. Restricted and privately bound Files are omitted. `includeChildren` governs reachable descendant folders; a selected folder lists its own Files. DOWNLOAD listings contain `/api/v1/public/folders/:token/download?fileId=...` authorization paths. This auxiliary operation checks the same live tree at issuance and redemption. Moving a File or ancestor out removes capability access, including through previously issued grants. Trees and per-folder File listings are bounded at 1000 resources.

`maxDownloads` counts verified byte deliveries, not metadata reads or issued paths. Grant consumption, counter increment and PUBLIC_LINK_DOWNLOADED/FILE_DOWNLOADED audit/outbox evidence commit together before bytes are released. Storage failures retain the allowance and grant for retry. Concurrent requests cannot exceed the limit, and source changes during storage I/O roll back stale consumption. PostgreSQL independently rejects counters above their cap and consumption proofs without matching recorded download accounting. Delivery proofs remain retained after capability purge. Shared signing-secret, whole-file buffer and response header requirements follow `FILES.md`.
